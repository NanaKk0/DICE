# Run the CPU demonstration

After [installation](install.md), remain in the DICE checkout with its control
environment activated. The demonstration creates all inputs for you and uses
synthetic backend services. No native training, molecular dynamics or FP
calculation runs.

## Complete two rounds

```sh
python examples/cpu_mock/run.py /tmp/dice-first-demo
```

Choose a new or empty directory. Success prints `Synthetic demonstration
complete` and the terminal `iter0/fp/selected.xyz` path. The workflow executes
teacher preparation, student rounds r0/r1, screening and final selection.

| File or directory | Inspect it to understand |
| --- | --- |
| `run.json` | The complete scientific configuration generated by the example |
| `iter0/teach/` | Teacher training, initial student labelling and reference preparation |
| `iter0/r0/`, `iter0/r1/` | Each round's training, synthetic sampling and screening |
| `iter0/fp/selected.xyz` | Final FP selection; an empty selection can be valid |
| `iter0/status.log` | Lifecycle progress and attempts |
| `iter0/dice.log` | Scientific screening report |
| `.dice_state/` | Workflow-owned operational records; leave these files managed by DICE |

## Continue the completed result

```sh
python examples/cpu_mock/run.py /tmp/dice-first-demo --reuse
```

This uses the existing inputs. A complete, valid terminal result is reused;
ordinary continuation does not intentionally force model retraining.

## Practise an explicit rebuild

```sh
python examples/cpu_mock/run.py /tmp/dice-first-demo --resume r1/sample
```

This deliberately rebuilds r1/sample and the remaining current-iteration
suffix in this disposable demo directory. r0 is outside that requested suffix.
For a scientific run, first inspect the intended boundary using the
[recovery commands](recovery.md).

## Return synthetic FP labels to iter1

```sh
python examples/iteration_handoff/check.py /tmp/dice-first-handoff
```

Use another new directory. This separate example runs iter0 and iter1,
constructs synthetic returned labels and checks their ingestion. Its
[guide](../examples/iteration_handoff/README.md) explains what carries over.

The fixture's small quotas, temperatures and step counts demonstrate
coordination. They are not recommended scientific settings. Read the
[workflow](workflow.md) and then [prepare your own system](own-system.md).
